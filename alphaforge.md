# День 1 – Fixed 20-Asset Universe

## Что сделали

Мы сделали первый базовый слой агента – **список разрешённых активов и проверку этого списка**.

По правилам хакатона агент может торговать только 20 бумагами ArenaGo. Это не рекомендация, а ограничение соревнования. Если агент начнёт работать с лишним тикером, это уже архитектурная ошибка.

---

## 1. Зачем вообще нужен этот блок

Перед тем как агент начнёт считать сигналы, стратегии и риск, он должен понимать:

- какие акции существуют в рамках соревнования
- какие акции разрешены
- какие акции отключены
- какие акции более рискованные
- какие акции более ликвидные
- какая максимальная доля портфеля допустима по каждой акции

Без этого агент будет работать вслепую.

---

## 2. Что теперь знает агент

Агент теперь знает фиксированный список из 20 бумаг:

```text
LKOH, SBER, ROSN, GAZP, VTBR,
YDEX, PLZL, T, NVTK, X5,
GMKN, MGNT, ALRS, AFLT, CHMF,
NLMK, MOEX, SNGSP, MTSS, PIKK
```

Также по каждой бумаге он знает базовые параметры:

| Поле | Что означает простыми словами |
| --- | --- |
| `ticker` | Код акции |
| `sector` | Отрасль компании |
| `liquidity_tier` | Насколько легко купить/продать бумагу |
| `risk_profile` | Стартовая оценка риска |
| `enabled` | Можно ли сейчас использовать бумагу |
| `max_weight` | Максимальная доля портфеля в этой бумаге |

---

## 3. Какие файлы сделали

### `configs/universe.yaml`

Это конфигурационный файл со списком всех разрешённых бумаг.

Пример:

```yaml
ticker: SBER
sector: banks
liquidity_tier: 1
risk_profile: balanced
enabled: true
max_weight: 0.10
```

Перевод:

> SBER – банковская акция,  
> достаточно ликвидная,  
> со сбалансированным риском,  
> разрешена для торговли,  
> максимальная доля в портфеле – 10%.

---

### `alphaforge/market/universe_scanner.py`

Это модуль, который читает `universe.yaml` и проверяет, что с ним всё нормально.

Он проверяет:

| Проверка | Почему важно |
| --- | --- |
| Все 20 бумаг есть | Агент видит весь доступный рынок |
| Нет лишних тикеров | Агент не нарушает правила соревнования |
| Нет дублей | Одна акция не считается дважды |
| Есть включённые бумаги | Агенту есть что анализировать |
| Поля заполнены корректно | Следующие модули не сломаются |

Если конфиг плохой, scanner не пропускает его дальше.

---

### `alphaforge/core/schemas.py`

Добавили строгие структуры данных.

Это значит, что агент передаёт между модулями не случайные словари, а нормальные объекты.

**Плохо:**

```python
{"ticker": "SBER", "risk": "medium"}
```

**Хорошо:**

```python
UniverseAsset(
    ticker="SBER",
    sector="banks",
    liquidity_tier=1,
    risk_profile="balanced",
    enabled=True,
    max_weight=0.10,
)
```

Это снижает риск скрытых ошибок.

---

### `tests/test_universe_scanner.py`

Добавили тесты.  
Они проверяют, что scanner:

- загружает 20 активов
- отклоняет лишний тикер
- отклоняет дубли
- ловит пропущенные тикеры
- возвращает только включённые бумаги
- не падает на пустом или отсутствующем конфиге

---

## 4. Как это повлияло на агента

| Было | Стало |
| --- | --- |
| Агент не знает, какие бумаги разрешены | Агент знает разрешённые 20 бумаг |
| Агент может случайно обработать лишний тикер | Агент блокирует неизвестные тикеры |
| Нет базовой информации о риске и секторе | Агент знает сектор, риск и лимит по каждой бумаге |
| Нет проверки конфига | Агент умеет отключать отдельную бумагу через config |
| Следующие модули могут получить мусор | Агент отдаёт чистый список активов следующим модулям |

---

## 5. Важное уточнение про риск

Мы **не вычислили** реальный риск акции.  
Мы задали **стартовую ручную классификацию**:

```text
SBER – balanced
MTSS – defensive
YDEX – volatile
AFLT – volatile
```

Это не истина. Это начальное предположение.

Настоящий текущий риск будет считаться позже в `feature_engine.py` по рыночным данным:

- волатильность
- объём
- просадка
- движение цены
- RSI
- положение цены относительно средней

Правильная логика такая:

> ручная классификация из `universe.yaml` + фактические данные рынка = нормальная оценка торговой возможности

## 6. Что агент теперь может

После Day 1 агент может:

- загрузить список разрешённых активов
- проверить список на ошибки
- отфильтровать запрещённые тикеры
- получить список активов для анализа
- отключить отдельные бумаги через config
- передать валидный `universe` дальше в pipeline

---

## 7. Что агент пока не может

Он ещё не умеет:

- читать цены
- считать доходность
- считать волатильность
- считать RSI
- понимать тренд
- находить лучшие акции
- выдавать BUY / SELL / HOLD
- строить торговую гипотезу

Это следующий слой.
